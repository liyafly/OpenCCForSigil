# OpenCCForSigil UI 与处理范围优化实施方案

日期：2026-09-07。状态：部分实施于 v0.0.2-beta，保留作历史设计与验收记录。
本方案并未整体完成；分组文件预览、返回设置、暂存/验证阶段取消，以及完整的跨平台真实阅读器验收仍待完成。已实施范围与剩余限制见
[`release-review-v0.0.2-beta.md`](release-review-v0.0.2-beta.md)。

## 1. 目标与边界

让用户先选择界面语言、转换方向和处理文件，再开始分析；用清晰的文件级预览确认修改，避免每次都分析整本书。

本轮必须交付：简体中文、English、繁體中文三语界面；单文件、多文件、全部 XHTML 三种处理方式；空选择保护；按文件预览；进度、取消、完成与失败反馈。

沿用现有 Qt 界面和官方内置 OpenCC，不增加 UI 框架，不增加运行时 pip、联网安装或转换后端替代方案。保持现有源码保护、预览决策、暂存、校验、最终写回边界。UI 语言与书籍转换方向是独立设置。

不在本轮实现自动识别整本书语言、选中文字转换、规则编辑器、历史版本恢复、额外字体处理或发布体系重构。自动识别并非开始转换的前置条件。

## 3. 主流程与窗口布局

```text
启动 → 读取偏好与文件清单 → 任务设置 → 校验目标与后端
     → 仅分析目标文件 → 按文件预览 → 暂存与结构校验 → 写回 → 结果摘要
```

建议任务窗口：

```text
OpenCCForSigil                     界面语言 [简体中文 ▾]

转换方向 [简体 → 台湾繁体（含台湾词汇） ▾]
说明：同时转换字形与地区词汇。配置：s2twp

处理范围  ○ 单个文件   ● 选择文件   ○ 全部 XHTML
已选择 3 / 28 个 XHTML                  [选择文件…]
Text/chapter01.xhtml、Text/chapter03.xhtml、Text/note.xhtml

高级选项 ▸
                                       [取消] [分析并预览]
```

语言选择始终可发现；转换方向使用自然语言说明，技术配置 ID 放在辅助说明中。保留所有当前可用的官方配置，按“简繁转换 / 地区字形与词汇 / 日文相关”分组展示，不根据 UI 语言推断方向。

高级选项默认折叠，仅放已有的官方 Jieba 能力开关；不支持时禁用并显示简短原因，详细载荷与 ABI 信息放入错误详情。保留上次有效转换方向与 Jieba 选择；载荷能力变化时显示降级说明并要求用户通过“分析并预览”确认本次设置。

## 4. 三语界面

### 4.1 语言与默认值

| 稳定代码 | 下拉框始终使用的自称 |
| --- | --- |
| zh-Hans | 简体中文 |
| en | English |
| zh-Hant | 繁體中文 |

首次启动优先匹配 Sigil 界面语言，再匹配系统语言，最后回退 English。已有用户明确选择时优先使用其选择。支持大小写及下划线归一化：zh-CN/zh-SG → zh-Hans，zh-TW/zh-HK/zh-MO → zh-Hant；明确的 Hans/Hant 脚本优先于地区；无地区 zh → zh-Hans，其他未支持语言 → en。

通过适配器读取 `bk.sigil_ui_lang`：当前上游定义为属性，不应直接当函数调用。针对旧版本/测试替身统一处理缺失和不同返回类型，不向 UI 泄漏 bk。

在任务设置窗口切换后立即刷新当前窗口，不改变转换配置、文件勾选和高级选项；后续窗口沿用所选语言。分析和写回期间不提供语言切换。语言选择可立即保存，即使用户随后取消转换也生效。

### 4.2 实现约定

新增 `ui/i18n.py` 与 `resources/i18n/{zh-Hans,en,zh-Hant}.json`，使用稳定 key 和具名占位符，例如 `scope.selected_count` / `{selected}` / `{total}`。三份目录键集合与占位符必须一致；禁止对 UI 文案临时调用 OpenCC 自动翻译。

覆盖窗口标题、按钮、提示、配置显示名、空状态、进度、结果和错误摘要。文件名、原文、转换结果、配置 ID、日志事件 ID 不翻译。缺失 key 在运行时回退 English 并记录诊断，在测试中必须失败；不向用户显示内部 key。

繁体界面统一使用经人工审阅的用词，如“檔案、套用、取消”；地区转换规则仍由独立的 OpenCC 配置决定。数量句式避免英文单复数错误。

## 5. 处理范围：先选文件，再读取正文

### 5.1 三种范围的定义

| 入口 | 文件来源 | 行为 |
| --- | --- | --- |
| 单个文件 | 明确选定的一个 XHTML | 显示完整相对路径，可用下拉框更换 |
| 选择文件 | 启动前 Sigil 书籍浏览器选择 + 插件内勾选调整 | 可处理任意多个 XHTML，无须退出插件重新选择 |
| 全部 XHTML | 当前书籍 text_iter 清单 | 显示准确数量，用户主动选择才使用 |

插件内文件选择器提供文件名/路径搜索、复选框、已选数量、全选可见项、清空可见项。过滤不改变隐藏项的勾选；按钮明确标注“可见项”，同时显示总选中数量，避免误解。按书脊顺序排列正文，其余文件按路径稳定排序，存储身份使用 manifest ID，不用 basename 匹配。

首次进入：有效所选 XHTML 为 1 个时预选“单个文件”；多个时预选“选择文件”；没有时显示空的“选择文件”并引导勾选。每次启动重新解析选择，不跨书保存文件 ID，也不自动恢复上次“全部 XHTML”。

### 5.2 “当前文件”必须明确能力边界

已核验的 `selected_iter()` 表示启动前 Book Browser 的选择，并不保证它就是编辑器活动标签页。检查过的本地 API 指南与上游 BookContainer 未发现可直接据此确认活动标签页的接口。上游来源见末尾。

实施第 1 步在目标 Sigil 版本实测：打开 A 标签页、在 Book Browser 选择 B，再启动插件；记录传入选择。不得把 selected_iter 首项、书脊首项或文件列表首项当作当前编辑文件。

本轮可落地基线是“单个文件”，显示明确路径；单选自动带入，多选/无选时由用户选择一个文件。这满足只处理一个文件的需求，但不宣称自动跟随活动标签页。

若实施时发现公开且可验证的活动文件 API，可增加“当前编辑文件”快捷项：解析到有效 XHTML 才启用，启动时冻结文件 ID，并测试活动标签与书籍浏览器选择不一致的情况。否则显示“请在书籍浏览器单选目标文件，或在这里选择文件”。真正自动识别活动标签页列为有条件功能，验收报告必须注明支持/不支持及 Sigil 版本。

### 5.3 范围与读取约束

1. 启动设置阶段只枚举 manifest、书脊和选择信息，不调用 readfile 读取书籍正文，不调用转换器分析正文。
2. 点击“分析并预览”后解析出不可变、去重、有序的 `TargetSelection(file_ids, scope_kind)`。范围解析应为可独立测试的纯逻辑。
3. 非 XHTML 选择显示“已忽略 N 个非 XHTML 文件”；有效集合为空时禁用分析。全书无 XHTML 时直接显示空状态。
4. `ALL_XHTML` 包括清单中的 XHTML（含 XHTML 导航）；界面写“全部 XHTML（含 XHTML 导航）”，不称“所有 EPUB 资源”。NCX、OPF 元数据、CSS、图片和字体不因“全部”而进入转换。
5. 分析、预览、暂存和写回全过程只使用冻结集合。对未选文件 readfile/writefile 次数都必须为 0。提交前源哈希复查仅限将写回的目标文件。
6. 目标 ID 失效时明确报错并返回设置，绝不扩大范围或自动改成全书。选择器能力缺失时仍允许插件内手动选文件。

这项优化减少插件正文解析和转换工作；不承诺减少 Sigil 启动插件时自身的 EPUB 准备或临时目录复制开销。

## 6. 预览与结果交互

预览左侧按文件列出“变更数 / 待决定数”，默认定位到首个有变化文件；右侧显示当前文件的变更列表和转换前后上下文。未改变的文件可折叠显示，统计仍计入已分析数量。文本按纯文本展示，不将 EPUB 内容渲染为可执行 HTML。

并列提供：接受此项、跳过此项、接受本文件、跳过本文件、接受全部文件、跳过全部文件。全局按钮含“全部文件”字样，且作用于本次目标集合全部变更，不受列表过滤影响；每项决定可反向更改。

保留显式决策要求：待决定数大于 0 时禁用写回。接受数为 0 时提供“完成（不修改）”；有接受项时按钮写“应用到 N 个文件”。按钮附近显示范围、方向、接受数量，避免再增加无信息量的确认弹窗。

支持“返回设置”：提示本次预览决定会清除，用户确认返回后释放旧计划，重新设置、重新分析，不能复用旧配置生成的偏移或变更 ID。

无变化直接显示“已分析 N 个文件，没有需要转换的内容”，提供“返回设置 / 关闭”，不弹空预览。完成后显示已分析文件数、实际修改文件数、接受和跳过变更数；说明结果已写回 Sigil，保存 EPUB 仍由用户在 Sigil 中完成。

## 7. 进度、取消与异常

显示真实阶段：检查运行环境、分析第 i/N 个文件（路径）、准备修改、验证修改、写回、完成。未知工作量用忙碌指示，不显示虚构百分比。后端检查可以先于正文分析，但主窗口应尽早可见。

设置、分析、预览、暂存和验证阶段允许取消；取消后清理本次临时计划和暂存，零 writefile。进入写回阶段禁用取消和重复提交，关闭窗口也不能中断写回。修改 session 的合法迁移，覆盖验证取消、返回设置、零变化和零接受路径。

首版使用 Qt 定时调度的逐文件增量步骤保持窗口响应；单个超大文件不能因此切碎送给 OpenCC。若性能基准发现单文件长时间阻塞，改为专用工作线程执行纯转换：同一后端实例只归属一个线程，Qt 控件只由主线程更新，bk 访问留在控制线程。取消在安全检查点生效，说明“正在停止，将在当前分析步骤结束后停止”，不强制终止 native 调用。

错误摘要采用用户语言，并提供可展开详情/复制诊断。区分未选择文件、读取失败、后端缺失/不兼容、源内容变化、结构校验失败与写回失败。日志不记录全文，新增 scope_kind、目标数量、阶段、耗时和失败位置即可。

写回失败时不能统一报告“未修改任何文件”：当前适配器逐个写入，应记录已成功调用 writefile 的文件集合与失败目标，说明本次失败、Sigil 最终接纳状态需检查。不得新增未经验证的“已自动回滚”或“可一键撤销”承诺；真实宿主失败与撤销行为纳入手动验收。

## 8. 可用性与性能细节

- 跟随 Qt/Sigil 字体、缩放与明暗主题，避免固定文字宽度；至少检查三语、长路径、125%/200% 缩放。颜色之外用文字标记接受/跳过状态。
- 设置合理 Tab 顺序、标签关联、可见焦点；Enter 在设置页触发分析，在预览页不得未经显式决策触发全书接受；Escape 在写回前取消。
- 长路径允许复制，列表使用省略显示与完整路径提示；不同目录同名文件可辨认。
- 预览使用 Qt 模型/视图或分页，避免为每个变更创建大量控件；分页只影响展示，不改变源字符串或转换上下文。
- 不先分析全书再过滤文件；不为了自动判断方向做额外全书转换；保持配置明确、后端实例按本次任务复用。

## 9. Luna 实施顺序与建议提交

每阶段先检查当前差异，保留已有工作；实现、测试、再提交。以下为建议 commit 边界，不要求本方案编写阶段提交或 push。

| 阶段 | 建议提交主题 | 主要改动 | 完成条件 |
| --- | --- | --- | --- |
| 1 | `feat: resolve explicit conversion file targets` | sigil/scope.py、adapter.py；新增 scope 解析测试；记录宿主选择实验 | 单文件/多文件/全部集合正确，未选文件零读写；当前文件能力已说明 |
| 2 | `feat: add three-language UI catalogs` | ui/i18n.py、三份 JSON、preferences.py/storage.py 接入 | 键和占位符一致，语言匹配、持久化和回退测试通过 |
| 3 | `feat: configure conversion scope before analysis` | ui/main_window.py、文件选择器、controller.py、workflow.py | 设置先于正文读取，范围冻结，旧偏好可迁移 |
| 4 | `feat: improve file-based preview decisions` | preview_window.py、纯 UI 状态模型、core/preview.py 必要接口 | 文件级与全局决策准确，返回设置不带旧计划 |
| 5 | `feat: report conversion progress and outcomes` | workflow 增量执行、session.py、进度与结果窗口、错误诊断 | 取消零写回，提交防重入，失败计数真实 |
| 6 | `test: verify localized scoped conversion flows` | 集成测试、UI 测试、README 使用说明、docs/testing.md | 回归和宿主手测完成，三语资源进入最终 ZIP |

实现时新增不可变 `ConversionOptions`（config、segmentation、target_selection），与 UI 展示状态分离；i18n 不进入转换核心。建议给 workflow 增加明确 targets 参数：新 UI 必须传入冻结 targets；若保留旧 scope 参数供兼容调用，定义互斥规则，空 targets 不能回退为 ALL_XHTML。

一个插件调用只维护一个 QApplication 生命周期，设置/进度/预览/结果窗口复用，避免现有两处窗口入口分别创建/退出应用带来的生命周期问题。

偏好新增 `ui.language`；窗口尺寸等可保存在 ui 下。读取保留现有未知键与 last_conversion_config，不保存本次文件 ID 或自动恢复全书范围。若需 schema 升级，提供旧版、损坏类型、未知语言的迁移测试。

## 10. 自动化验收

新增测试文件名可按仓库规范调整，但必须覆盖以下可观察结果，不能只测试枚举值或文案常量。

| 测试组 | 场景与断言 |
| --- | --- |
| 范围隔离 | 假 BookContainer 含 A/B/C 和图片；选 B 后仅 B 被读与可能写；多选 A/C 时 B 零读写；所有写入属于冻结集合 |
| 空与异常选择 | 空选择、只选图片、重复 ID、失效 ID、selected_iter 缺失；不误用全书，不重复读取，提供明确状态 |
| 读取时机 | 打开设置、改语言、过滤文件列表、取消设置时 readfile=0；分析后才有目标读取 |
| 全部范围 | XHTML 导航与非书脊 XHTML 纳入；NCX/OPF/CSS/图片不纳入；单选目标与排序可预测 |
| 三语 | 三份 key/占位符匹配；Sigil 属性语言映射；明确偏好覆盖宿主；切换语言不改变方向和文件选择；英文数量表达正确 |
| 预览 | 本文件接受不影响其他文件；全局操作覆盖所有目标文件；待决定禁止应用；零接受零写回；返回设置后旧决定无效 |
| 取消与终态 | 各可取消阶段零写回；无变化正常完成；写回防重入；验证失败与源变化阻断全部写回 |
| 部分失败 | 第二个 writefile 抛错，摘要不能宣称零写入/完整成功；记录已成功调用与失败目标 |
| 源码保护 | 保留现有 protected elements、属性、锚点、实体和结构校验回归；未选文件字节不变 |
| 打包 | 三份语言资源存在于插件 ZIP，能够通过打包后的路径加载；不依赖工作区源目录 |

Qt 控件测试使用项目现有支持的 Qt 绑定，测试依赖留在开发环境；不得为测试向发行插件加入 PyQt/PySide 载荷。纯逻辑可用测试替身，但不能用替身测试通过代替真实窗口运行证据。

执行命令（实施后）：

```sh
mise exec -- uv sync --locked
make check
mise exec -- uv run python tools/build_plugin.py --output dist/OpenCCForSigil_ui-review.zip
mise exec -- uv run python tools/validate_artifact.py dist/OpenCCForSigil_ui-review.zip
```

用于发布的最终跨平台 ZIP 仍必须按 `docs/testing.md` 对完整 runtime 矩阵运行 `--require-runtimes`；本地单平台包通过不代表全部平台验收通过。UI 资源变化应复用已验证 native 载荷，不因本轮交互变化重编原生依赖。

## 11. 宿主手动验收与性能记录

准备固定 EPUB：至少 5 个正文 XHTML、XHTML 导航、非书脊 XHTML、同名不同目录文件、图片/CSS、受保护 code/script/pre 内容；另准备大书样本。记录 Sigil 版本、OS/架构、实际插件 Python/Qt 版本和样本大小。

1. 在三种语言下分别走单文件、多文件、全部 XHTML，从设置到预览、结果与错误详情无混杂界面文案。
2. 活动标签 A、书籍浏览器选择 B，验证窗口准确显示真实目标；不得转换 A 却宣称来自 B，反之亦然。
3. 不在 Sigil 预选文件也能在插件内选择 1 个或多个文件；选图片/空选择不会启动全书分析。
4. 修改方向、接受某文件、跳过另一文件，保存输出 EPUB；比较 ZIP 解压后的条目内容，未选文件及未接受文件字节不变，不比较 ZIP 压缩元数据。
5. 在分析、预览和验证阶段取消，检查书籍未写回；全部跳过与无变化都正常结束。
6. 写回成功后检查 Sigil 中的实际结果与保存后的 EPUB；在测试副本验证宿主失败与撤销行为，记录观察，不预设承诺。
7. macOS arm64、macOS x86_64、Windows x86_64、Linux x86_64 均完成最小设置→分析→预览→写回流程；三语和缩放布局每种 OS 至少完成一次。暂缺平台必须标记“未验证”。

性能以同一机器、固定样本、同一 backend/config 的改动前后对比，至少重复 3 次报告中位数：插件进入设置耗时、设置→预览耗时、峰值内存、readfile 调用集合、变更数。分别测试小书、大书选 1 个、大书选 3 个、大书全选和单个超大 XHTML。

硬性门槛：设置页正文读取 0；选 k 个文件时首次分析每个目标只读一次（提交源哈希复读另计），未选文件零读取；结果与原范围对应转换一致。交互目标：普通多文件样本阶段间取消响应不超过 1 秒，预览万条变更仍可滚动操作；如单文件 native 转换超过此目标，记录最大等待并落实第 7 节线程方案或明确取消边界，不能把整文件强拆来凑时延。

## 12. 最终交付清单

- [ ] 三语完整且可切换、记忆，不影响转换内容。
- [ ] 单文件、多文件、全部 XHTML 可用，先选择后分析。
- [ ] 当前编辑文件的支持边界有实测记录，没有伪造自动识别。
- [ ] 预览按文件决策，写回范围及数量清晰，取消和错误反馈准确。
- [ ] 自动测试、打包资源验证、宿主和性能记录齐全；未验证项明确列出。
- [ ] Luna 提交交付说明：commit 列表、测试命令与结果、手动验证平台、剩余限制。

本轮新发现、必须优先处理的问题（批次 1）：

| 条目 | 问题 | 后果 |
| --- | --- | --- |
| A-01 | 书里出现土耳其字母 `İ`，而且后面有 `<style>` 或 `<script>` | 分词器死循环，取消无效，只能强制结束 Sigil |
| A-04 | 全部写回成功后，写日志失败（例如磁盘满） | 插件返回非 0，Sigil 丢弃整次转换，界面却说"已写入" |
| A-03 | 单个文件里有大量 `&#12288;` 这类实体（网文常见） | 规划时间按平方增长：16000 段需要 34 秒 |
| B-01 | 上次用过 Jieba | Jieba 复选框取消不掉 |
| B-02 | 打开设置对话框 | 探测计时器永不停止，每 50 ms 重建一次下拉框 |
| B-03 | 无变化结果框里按 Esc | 回到文件选择，而不是关闭 |
| N-01 | Jieba 不可用的机器上运行自检 | 误报核心转换失败（重构时引入的回归） |
| N-02 | 保存过以 t2s 结尾的强制中转链 | 打开设置对话框时被换成另一条链，并写回偏好 |
| N-03 | 任意未改动的方案 | 显示"（已修改）"，不能重命名、删除 |

其次是转换正确性（批次 2、3）：
- 一个词组映射会被拆成几条可以分别接受的变更，部分接受会写出错字（A-02）；
- `<m:math>`、`<svg:svg>` 前缀写法不受保护（A-06）；
- `<script>` 的 CDATA 里出现 `</script>` 时，后面的代码被转换（A-07）；
- 保护规则会被重叠的转换规则抢先（A-08）；
- verifier 不检查"只改了计划内的地方"（A-05）。

性能（批次 4）：100 万字的书规划 13–15 秒，预览里每点一次约 0.5 秒。改两处（D-01 等长按位置对比、D-02 预览按需格式化）可以降到约 6 秒和 30 ms 以内。

# OpenCCForSigil 功能与 UI 工作流优化：Luna 执行规格

日期：2026-09-27。实查基线：`main` / `b9ffacfdffdebc16cbb1f8e42447f9cc0a1133aa`，代码版本 `0.2.8`。

建议下一轮围绕一个目标：**让用户清楚知道本次会改什么，方便逐项审校，能够复用自己的设置。** 优先修复摘要不真实、窗口无法适应内容的问题，再增加本次设置摘要、待决定项批量处理、方案比较与历史检索。保持原生 Qt 风格，以布局、状态和操作范围解决问题。

本文是待实施规格。此次交付只包含文档、复现探针和当前版本证据，插件功能没有修改。文中“必须”“通过”描述未来验收要求，当前结果以第 2 节为准。

### 2.2 根因和机会点

- `ui/run_options.py:RunOptionsPanel._update_profile_label()` 已构造本次 `current`，但规则摘要仍读 `active.builtin_rules_enabled` 和 `active.ruleset_ids`。当前证据证明显示错误，没有证明转换错误。
- `ui/profile_window.py:ProfileManagerDialog._build()` 为所有规则集直接创建纵向复选框，没有受限滚动区域；方案本身已有列表和详情，但没有搜索和差异比较。
- `ui/window_state.py:restore_window_size()` 只校验正整数；规则窗口另有自己的屏幕限幅函数，预览又自行恢复尺寸，行为不一致。
- `ui/preview_window.py:_PreviewDialog._build()` 将当前项、文件、筛选、全局、撤销、报告操作并列。原批量操作会明确覆盖已有决定，缺少“一次只处理未决定项”的独立入口。
- `ui/rules_window.py:RuleManagerDialog._build()` 在同一个长滚动区域排列规则集、说明、表格、详情、冲突、编辑器、导入导出和测试。搜索、草稿保护、冲突跳转、沙箱本身已经存在。
- `ui/history_window.py:show_history()` 已有排序、打开、导出、清理和 session ID 映射；缺少过滤，打开/导出在无选择时还会进入“请选择”的提示路径。

## 3. 全局边界与交互约定

### 3.1 保持的行为

1. 继续使用 vendored 官方 OpenCC；转换结果、规则优先级、regex 预算、保护区间、源偏移及原生包矩阵均不属于本轮重写范围。
2. 设置、筛选、比较、预览决定不触发 `bk.writefile()`；摘要、布局、搜索、方案比较不调用 OpenCC，不为显示结果读取 EPUB 正文。沙箱显式“测试”继续按现有逻辑调用转换。
3. 预览 Undo/Redo 只撤销本次预览决定；Apply 仍要求全局无未决定项。返回设置仍使旧计划、旧决定和历史失效。
4. 同一次规则替换组不可拆开；跨文件语言标签组不可拆开；相同 rule ID 的不同出现仍是不同组。文件级操作继续排除跨文件语言标签组，不能把它隐含纳入“本文件”。
5. UI 新偏好只能存窗口尺寸、分隔条等展示状态。搜索词、文件选择、正文、方案比较内容、决定历史不写入偏好或日志；已有 full diff 仍需每次显式选择。
6. 新文案覆盖 `resources/i18n/{en,zh-Hans,zh-Hant}.json`；保留用户自定义名称和输入原文。原生主题、系统字体、可见焦点优先，不使用整套硬编码颜色或全局 QSS 换肤。
7. fake Qt 只能证明状态逻辑；真实 Qt 证明布局与事件；真实 Sigil 才能证明安装和宿主行为。三层证据分别记录。

### 3.2 状态必须分清

| 名称 | 定义 | UI 应如何表达 |
| --- | --- | --- |
| 保存的方案 | 磁盘上已命名的 Profile | 显示名称；不可被临时勾选静默覆写 |
| 本次设置 | 用户当前控件选择，包含未保存修改 | 显示“已修改”，提供修改明细 |
| 本次有效设置 | 结合范围、可用能力后的实际运行参数 | 摘要以此为准；被禁用的保留偏好要说明本次不生效 |
| 引用的规则集 | 本次方案选中的规则集 | 不将“已引用”说成“每条都命中” |
| 已决定项 | 预览中的接受或跳过 | 默认的待决定批量功能必须保留 |
| 应用到书籍 | 通过 stage/verify 后提交 | 只由已有 Apply 路径执行 |

### 3.3 布局和尺寸标准

- 以下尺寸均为 Qt 逻辑像素。先用 960×640 验收紧凑布局，再用 1280×800 验收宽布局；若可用屏幕更小，窗口适配屏幕，内容通过局部滚动到达。
- 恢复尺寸按当前窗口所属屏幕的 `availableGeometry` 限制，建议每侧留 16 像素。无关联屏幕时取主屏幕，仍无屏幕才用现有默认值。最小布局本身也要可收缩，不能只调用 `resize()`。
- 底部关闭、取消、保存/使用/应用按钮始终可达；主要列表独立滚动，不要求滚动整个窗口才能点击提交动作。无横向拖动顶层页面的操作要求，表格/代码文本内部横滚允许。
- 125% 和 200% 缩放在独立进程检查，注明 screen/devicePixelRatio。不能用截图放大冒充高 DPI 验收。
- 长名称省略显示并提供完整 tooltip；不同目录同名文件在详情中显示完整 href。禁用按钮有可见原因，不能只靠灰色说明。

## 4. 分批实施规格

### UX-01：让规则摘要与本次运行一致

**用户结果：** 用户关闭内置署名保护后，不会在同一页面看到“已启用”。

修改入口：`ui/run_options.py` 的 `_update_profile_label()`，必要时提取纯展示数据函数；正式回归放 `tests/unit/test_run_options.py`，关联检查 `test_profiles_m3.py`、`test_i18n.py`。

实施要求：

1. 摘要使用已经构造的本次 `current`。内置规则包的“启用”表示功能开关，不能写成当前方向一定存在规则或一定命中。
2. 规则集名称/ID 以本次有效引用为准，缺失规则集继续走既有恢复提示，不由标签刷新消费或清除提示队列。
3. 勾选、方向变化、方案载入、保存为方案、规则窗口返回后及时刷新；显示变化不得保存 Profile。

验收：

- [ ] 保存方案 true → 本次取消：勾选 false、有效 Profile false、摘要“停用”；保存方案仍 true。
- [ ] 保存方案 false → 本次勾选：三者 true/启用；来回操作不生成新方案。
- [ ] 在 `tw2sp` 下比较冻结规则快照：开关确实控制内置规则；在 `s2t` 下只显示开关状态，不声称已命中署名规则。
- [ ] 三语言、方向切换、重新载入方案结果一致；缺失规则集提示仍出现一次，不能被刷新吞掉。

### UX-02：方案规模与窗口恢复不再破坏布局

**用户结果：** 规则集多、从大屏换到小屏后，仍能看到“使用/关闭”。

修改入口：`ui/profile_window.py`、`ui/window_state.py`；将 `ui/rules_window.py` 的现有尺寸限幅和 `ui/preview_window.py` 自行恢复尺寸路径接入一致逻辑，检查 `ui/history_window.py` 的调用。保持既有偏好 key。

实施要求：

1. 方案规则集区改成有界滚动选择列表或有界 `QScrollArea`，保留“仅用于本次运行”的说明；不要把 60 个复选框全部计入顶层最小高度。
2. 共用屏幕限幅助手，首次显示前后都要保证布局可用；重复恢复不累积缩小窗口。尊重合法小尺寸和现有未知偏好，不删除用户配置。
3. 长方案名、规则集名、空列表、恢复告警都不能把底栏推出窗口。规则集数量增加只扩大列表内容，不扩大顶层最小高度。

验收：

- [ ] 0/1/60/300 个可选规则集，30 个方案；960×640 下关闭/使用可见，滚动可到首尾项，首尾勾选状态准确。
- [ ] 800×600 可用屏幕上无顶层横向溢出，底部操作可见；不以隐藏说明或移除选项通过检查。
- [ ] 保存 `[4000, 3000]` 后在小屏恢复；结果在可用区域内。负数、bool、字符串、空数组继续回退；无屏幕测试替身不报错。
- [ ] 100 次列表选择/尺寸恢复不改任何转换参数；规则集选择取消后不保存，点击使用保持已有临时选择语义。
- [ ] 三语言 125%/200% 缩放及模拟换屏均留截图/geometry 数据；真实换屏未测则单列 `Not verified`。

正式回归：`test_window_state.py`、`test_profile_window.py`、`test_dialog_construction.py`。至少新增一个真实 Qt 多规则集布局回归；fake Qt 尺寸值不能作为通过依据。

### UX-03：在设置阶段看清本次会做什么

**用户结果：** 无论停在哪个设置标签页，都能确认选中的文件数量、方向、额外文档和高风险选项。

主入口：`ui/preview_window.py:choose_scope()` 的合并对话框，复用 `RunOptionsPanel`、`RunSettings.current_profile()`、`profile_options()`。建议纯展示数据放新文件 `ui/run_summary.py`，不把 Qt 文案塞进 core。

结构草图（复用现有两个标签页）：

```text
[文件范围] [转换设置]
┌ 当前页内容，独立滚动 ──────────────────────┐
│ 方案：我的方案（已修改） [查看修改] [另存为方案] │
│ 转换方向 + 简短说明；文档选项；[高级选项 · 2 项修改] │
└──────────────────────────────────────┘
本次：3 个 XHTML · s2twp · 附加 NCX · 元数据不变
注意：已启用强制中转                         [详情]
                                      [取消] [分析并预览]
```

冻结语义：

1. 只计最终本次 XHTML 选择；NAV 属于所选 XHTML，不重复加到文件数。NCX/元数据作为独立附加范围注明“全书”，未读取正文前不猜其中会变化的条目数。
2. 范围列表、方向、临时选项、方案切换后更新；当前代码只在确认时调用 `set_nav_available()`，本轮要让显示状态随范围变化同步，最终确认仍重复校验。
3. 有被禁用但仍被记住的偏好时写“本次不生效：所选范围没有 NAV”等原因；不因临时不可用抹掉偏好。Jieba pending/unavailable 使用已有状态，不能自动回退并继续分析。
4. 高级折叠标题显示“相对当前方案修改了 N 项”；标题提示隐藏的有效高风险项（如强制中转、元数据、regex，按当前模型和既有风险语义）。不要把已经保存但启用的高风险项藏在“0 项修改”背后。
5. “查看修改”为只读明细：字段 / 保存的方案 / 本次设置 / 本次有效值。没有磁盘保存方案时以本次打开时的初始设置为基准，标题明确“相对初始设置”。使用 typed 数据比较，排除 id/name/schema 等元数据，并复用 panel defaults 归一化。
6. 摘要最多两行；长规则集清单和详细参数放可展开详情。由 Profile 载入但面板未提供编辑控件的有效选项（例如 MathML）仍要在详情中可见。
7. 转换方向说明来自当前仓库配置与文案，例如 `s2t` 通用繁体、`s2tw` 台湾字形、`s2twp` 台湾字形及词汇；不增加自动推荐或自动改方向，不运行演示转换生成摘要。

验收：

- [ ] 三个正文文件 + 一个 NAV，选三个正文：显示 3、NAV 本次不生效；勾 NAV 后显示 4，不是 5。
- [ ] 同时开 NCX 和元数据，摘要分别列出全书附加范围；XHTML 计数不混入二者。
- [ ] 切到文件范围页仍能看到摘要；选空时分析禁用并有原因，不能回退全书。
- [ ] 带 Jieba 的方案在 probe pending/unavailable 时不能静默分析；强制中转在不兼容方向下摘要显示本次不生效、保留偏好。
- [ ] 折叠高级设置后，隐藏的修改与风险可见；展开/折叠不改参数。切换 UI 语言保留所有值与文件集合。
- [ ] 仅查看/比较设置时，正文 `readfile=0`、OpenCC 调用 0、Book 写入 0、Profile 保存 0。
- [ ] 新会话不会自动恢复上次文件集合；“返回设置”后重新分析不复用旧计划。

正式回归：新增 `tests/unit/test_run_summary.py`，覆盖 `test_run_options.py`、`test_scope_selection.py`、`test_dialog_construction.py`、`tests/integration/test_plugin_conversion.py`。

```text
├ [当前项详情] [诊断 4] ────────────────────────────────┤
│ 原文（含上下文）       │ 转换后（含上下文）              │
│ 来源、组联动范围；[源码上下文]                         │
└────────────────────────────────────────────────────┘
[接受此项] [跳过此项] [下一项待决定] [撤销] [重做] [更多…]
剩余 60 项待决定              [返回设置] [取消] [应用已接受的变更]
```

冻结语义：

1. 直接显示接受此项、跳过此项、下一项待决定、撤销、重做；恢复此项、批量操作、语言组操作和导出放“更多”菜单。含清除/展开按钮的主视图，显式可点击命令控件不超过 12 个；不把按钮改成无名图标来凑数。
2. 更多筛选默认折叠，包含文件、类别、风险、来源。任何非默认筛选以数量/简短摘要常显；“清除”清空所有条件。保留 AND 语义、140ms 搜索防抖、稳定 `(file_id, change_id)` 选择。
3. 详情采用原文/转换后两个只读区域，标示变化位置并有文字说明；“源码上下文”沿用原始偏移提取逻辑。纯文本方式显示 `<>&` 等内容，不能作为富文本执行或误渲染。
4. 类别列只放简短类别，冗长组描述移到详情。详情清楚标出“此操作联动 N 处 / M 文件”；语言组仍有专用入口，不能伪装成普通当前文件操作。
5. 诊断复用现有列表与定位，放独立详情标签以免挤压表格；标签总数来自计划，诊断过滤后的可见数另列。定位真实变更时切到当前项详情；纯诊断不制造 TokenChange。零变更结果窗口保留原诊断入口。
6. 导出打开小对话框，选择已有支持的格式和“包含完整差异”，后者每次默认为 false，不持久化；调用原导出服务，不改报告格式与隐私边界。
7. 旧的文件/筛选/全量覆盖动作在 UX-04 阶段完整保留在菜单中，明确范围；UX-05 再统一入口。按钮和菜单共享现有决定路径，不复制业务逻辑。
8. 表格焦点内的 A/S/N、撤销/重做保持；搜索框和文本区域拥有自己的输入、复制与撤销行为。Enter 不触发批量接受或 Apply，Esc 沿用草稿决定保护。

### UX-05：只批量处理待决定项，保留人工审校结果

**用户结果：** 先手动跳过几个不合适的修改，再把其余待决定项统一接受，不会把已跳过项反转。

入口：预览“更多 → 批量决定…”。一个小对话框提供范围、动作、是否仅处理待决定项、影响摘要；不新增默认自动接受流程。

| 字段 | 默认和语义 |
| --- | --- |
| 范围 | 默认“当前筛选结果”；可选“当前文件”“全部文件”；无当前文件时禁用对应选项并说明 |
| 动作 | 接受 / 跳过；默认接受，但打开窗口不执行 |
| 仅处理待决定项 | 默认勾选；每次打开重置为勾选，不存偏好 |
| 取消勾选 | 显示“将覆盖 N 个已决定项”，用明确确认按钮文案；N=0 时正常表述，不凭空警告 |
| 影响摘要 | 实际将变化 X 处、完整组 G 个、涉及 F 文件、筛选外 H 处；另列保留/排除原因及数量 |
| 执行按钮 | X=0 时禁用；显式点击一次后形成一个可 Undo 的动作，不 Apply 书籍 |

计算规则必须先实现为可单测的纯逻辑，建议放 `ui/preview_batch.py`：

1. 输入是冻结计划、当前决定快照、当前筛选 identities、选定 file ID；不能从当前表格行号推断全局范围。
2. 一个无组的项视为一个决定单元；一个 group ID 的全部成员视为一个单元，先去重再计算。仅待决定模式下，单元的**所有成员**都未决定才纳入；发现混合状态则整组排除并给出计数，绝不部分改组。
3. 筛选范围命中组中一项，可以展开为整组；影响摘要必须列出隐藏成员数量及文件数。本对话框的显式确认可复用既有隐藏组确认，避免连续弹两次同样问题。
4. 当前文件范围：包含该文件无组项及规则出现组；跨文件语言标签组排除并显示原因，用户可走专用语言组或全部文件操作。全部文件范围包含所有单元。
5. 仅待决定关闭后允许覆盖原决定；目标状态已经相同的项不计入 X，不生成无变化历史。摘要同时明确覆盖数，不能把可见项数量当实际影响数量。
6. 一次确认只创建一次 Undo 记录；取消不改决定、不清空 redo、不创建历史。沿用现有历史预算，不能为大批量复制正文或逐项创建大型 UI 对象。
7. 快照只在本次弹窗内使用；执行前若决定修订已变化，刷新摘要并要求重新点击，不能把过期影响摘要当授权。正常模态流程不应发生，但接口测试需覆盖。

验收夹具与结果：

| 用例 | 输入 | 必须得到 |
| --- | --- | --- |
| B1 | 10 项：2 接受、3 跳过、5 待定 | 默认接受只改 5；总计 7 接受/3 跳过，Undo 恢复原 2/3/5 |
| B2 | 同 B1，关闭仅待定、接受全部 | 8 项实际变化、覆盖 3 个已跳过项；一个 Undo 恢复全部原决定 |
| B3 | 筛选命中 3 成员组中的 1 项 | 全组未定则影响 3、隐藏 2；取消零变化；确认完整联动 |
| B4 | 组有隐藏且已决定成员 | 仅待定模式整组不改；提供排除计数；不能拆组 |
| B5 | 本文件有规则组和跨文件语言组 | 规则组可纳入；语言组排除且解释；全部文件可完整处理语言组 |
| B6 | 同 rule ID 不同 occurrence group | 只改变范围命中的出现，不能按 rule ID 合并 |
| B7 | 空筛选 / 全部已决定 / 重复接受 | X=0 禁用；历史不增长，原 redo 保留 |
| B8 | Undo 后打开并取消 / 真正新动作 | 取消保留 redo；实际新动作才清空 redo |
| B9 | 300,000 项混合状态 | 两倍数据的访问计数呈线性增长；禁止逐组扫描全表；不复制 source/target 到历史 |
| B10 | 执行前决定修订变化 | 不执行旧影响集；刷新摘要后需要再次确认 |

正式回归：新增 `tests/unit/test_preview_batch.py`，关联 `test_preview_group_scaling.py`、`test_preview_decision_history.py` 和 `tests/integration/test_plugin_conversion.py`。B1/B3/B5 至少通过真实 Qt 用户入口测试。

### 6.2 真实 Qt 场景

在本目录新增 `scripts/check_ui_acceptance.py`，使用合成数据和临时存储，建议参数 `--output`、`--verify`、`--width`、`--height`。复用已有真实 Qt 脚本中的按键与交互方法；不是只 `show()` 后截屏。

`--verify` 必须实际断言：UX-01 状态一致、UX-02 窗口与底栏可见、UX-03 合并主入口摘要随选择变化、UX-04 控件数量及表格/详情尺寸、UX-05 B1/B3/B5、UX-06 草稿换页、UX-07 过滤后使用正确 ID、UX-08 过滤排序后正确 session ID。输出 JSON，含 HEAD、Python/Qt/OS/QPA、逻辑屏幕、DPR、各场景 PASS/FAIL。

```sh
# 以下脚本是 Luna 本轮应新增的交付物
QT_QPA_PLATFORM=offscreen mise exec -- uv run --with PySide6==6.11.2 python \
  docs/reviews/2026-09-27/ui-workflow/scripts/check_ui_acceptance.py \
  --output /tmp/opencc-ui-acceptance --verify --width 960 --height 640

QT_QPA_PLATFORM=offscreen QT_SCALE_FACTOR=1.25 mise exec -- \
  uv run --with PySide6==6.11.2 python \
  docs/reviews/2026-09-27/ui-workflow/scripts/check_ui_acceptance.py \
  --output /tmp/opencc-ui-125 --verify --width 960 --height 640

QT_QPA_PLATFORM=offscreen QT_SCALE_FACTOR=2 mise exec -- \
  uv run --with PySide6==6.11.2 python \
  docs/reviews/2026-09-27/ui-workflow/scripts/check_ui_acceptance.py \
  --output /tmp/opencc-ui-200 --verify --width 960 --height 640
```

三语言分别保留：合并设置页、预览默认/无匹配/诊断、批量影响摘要、规则编辑/测试、方案比较/60 规则集、历史筛选截图。另以 1280×800 检查宽布局；小屏实际尺寸以 clamp 后可用区域为准，不能在 offscreen 800×800 环境宣称验证了 1280×800 的屏幕适配。UI 改动前后使用相同字体和合成夹具。

人工查看截图确认无重叠、截断和不可读文案；geometry 通过不代表肉眼审查通过。真实 Qt 模拟明暗主题与三语；宿主原生深色和系统字体未测时单列说明。

## 7. 真实 Sigil 验收表

使用测试 EPUB 副本：3 个正文 XHTML、NAV、NCX、OPF、相同文件名不同目录、code/pre/ruby/MathML 保护内容；至少有普通变更、规则多成员组、跨文件语言组、只含诊断的文件。记录夹具 SHA-256。

| 编号 | 用户操作 | 通过标准 |
| --- | --- | --- |
| H1 | 打开插件，改范围/方向/高级选项/语言，再取消 | 摘要准确；未读取正文的 UI 操作符合自动断言；宿主书籍未被修改 |
| H2 | 手动接受 2、跳过 3；批量接受其余待定；Undo/Redo | 原手动决定保留，撤销一次恢复整批；Apply 前书籍未写入 |
| H3 | 筛选命中组一部分；查看批量摘要，先取消再确认 | 隐藏联动范围正确；取消零改变；确认按完整组处理 |
| H4 | 编辑规则草稿、换页、沙箱测试、返回、保存 | 草稿保护按 UX-06；保存才持久化；旧预览不能带修改后的规则继续提交 |
| H5 | 搜索方案、看差异、使用带高级选项的方案 | 没有扩大所选文件；差异与设置真实一致；不可用能力有明确阻断 |
| H6 | 打开历史，过滤排序，打开/导出某记录 | 正确 session；默认无全文；清理取消不改变历史 |
| H7 | 完成审校、Apply、保存 EPUB、关闭并重新打开 | 只修改接受且允许的源区间，未选文件及受保护源码保持一致；不能仅比较 ZIP 容器总哈希 |
| H8 | 三语言、长路径、缩放、小窗口、原生明暗主题 | 主动作可达，焦点/快捷键正确；Enter 不执行批量决定或隐式写回 |

每份记录包含：代码 SHA、ZIP SHA-256、插件版本、输入/输出 EPUB SHA-256、OS/架构、Sigil 版本、插件 Python/Qt、步骤、期望、实际、截图。一个平台通过不代表全部平台；无宿主记录不得勾 H1–H8。自动 spy 验证的零调用与宿主中观察到的未修改要分别描述。

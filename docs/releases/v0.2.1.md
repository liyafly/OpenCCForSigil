CPython ABI used by Sigil's plugin process. GitHub's automatically generated
source archives are not installable plugins.

Choose the Linux package whose CPython ABI matches Sigil's plugin process.
The standard Linux packages require CPython 3.14/cp314; the separate x86_64
package requires CPython 3.12/cp312. The Fat Plugin contains the five cp314
payloads and does not include the cp312 runtime.

## Changes

- Preserve the Taiwan-to-Simplified author-credit marker `◎【著】`, including
  with Jieba segmentation. Ordinary contextual conversion such as
  `慰藉著` → `慰藉着` remains unchanged.
- Add localized rule-writing help to the Rules / sandbox page, plus a detailed
  guide in the installable plugin package.

## Automated validation

The [main CI run](https://github.com/liyafly/OpenCCForSigil/actions/runs/36091403635)
passed all six native payload jobs, cross-platform Jieba comparison, repository
tests, package builds, and six runtime package smoke jobs at commit
`e6b9669307e61ce0168149c8724dbb9bc3da6419`. The [tagged release run](https://github.com/liyafly/OpenCCForSigil/actions/runs/36092076210)
at the same commit passed those jobs, generated and verified provenance
attestations for every release asset, and published this Release. Downloaded
assets also passed `tools/release_assets.py`, SHA-256 verification, and
independent attestation verification for all eight files. These checks do not
establish acceptance inside a real Sigil process.

Verify downloaded checksums with `tools/release_assets.py` and verify each
artifact's provenance with:

```sh
for asset in OpenCCForSigil_*.zip SHA256SUMS.txt; do
  gh attestation verify "$asset" \
    --repo liyafly/OpenCCForSigil \
    --signer-workflow liyafly/OpenCCForSigil/.github/workflows/ci.yml
done
```

The SHA-256 of the published `SHA256SUMS.txt` is
`d35b0df5518a60493d6a003cc8e8c42d680739da7eb6b87477218c2e0204b5a1`.
